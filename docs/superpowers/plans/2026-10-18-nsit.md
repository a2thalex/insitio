# nsit CLI and Insitio API v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `nsit`, a single-binary Rust CLI that people and agents use instead of `git` against Insitio, plus the `/api/v1`, device login and download pages it needs.

**Architecture:** The Insitio server (TypeScript/Hono) gains a bearer-token JSON API under `/api/v1`, a device-authorization flow with an approval page, and `/download` plus install scripts. `nsit` lives in `cli/` as a Rust crate: clap commands over a `git2` (statically linked libgit2) engine for all git work, `reqwest` for the API, and `keyring` for tokens. TypeScript e2e tests drive the real `nsit` binary against a real Insitio server.

**Tech Stack:** Server: existing Node + Hono + node:sqlite + Vitest. CLI: Rust 1.94 (MSVC on Windows), `git2 = 0.21` (features `vendored-libgit2`, `https`; `vendored-openssl` on Linux), `clap = 4.6` (derive), `reqwest = 0.13` (blocking, json, rustls), `keyring = 4.2`, `jaq-core 3.1` + `jaq-std 3.0` + `jaq-json 2.0`, `serde`/`serde_json`, `toml 1.1`, `dirs 7`, `regex 1.13`, `open 5`, `hostname 0.4`, `thiserror 2`, `anyhow 1`; tests `tempfile 3`, `assert_cmd 2`, `predicates 3`.

**Spec:** `docs/superpowers/specs/2026-10-18-nsit-cli-design.md` (evidence: `docs/rea-findings-cli.md`).

## Global Constraints

- Binary name `nsit`; product name Insitio; default host `git.iam.bot`.
- Must work with no git installed (git is a test-only dependency).
- Targets: `x86_64-pc-windows-msvc`, `x86_64-unknown-linux-musl`, `aarch64-apple-darwin`, `x86_64-apple-darwin`.
- Never accept a token as a CLI argument; never write a token into `.git/config`, remote URLs, logs or error text.
- HTTPS only, except `http://localhost`, `http://127.0.0.1`, `http://[::1]` (for tests).
- No prompts when stdin or stdout is not a TTY; no color when not a TTY or `NO_COLOR` is set.
- Exit codes: 0 success, 1 general error, 2 usage, 3 not signed in / auth failed, 4 merge conflict, 5 secret guard, 6 rejected by server.
- `--json` on every command that prints data; `--jq <expr>` implies `--json`; data to stdout, errors to stderr.
- Token resolution: `NSIT_TOKEN` → OS credential store (service `insitio:<host>`, account `<username>`) → owner-only token file beside the config (only when no credential store is available).
- Config: `%APPDATA%\insitio\nsit.toml` on Windows, `$XDG_CONFIG_HOME/insitio/nsit.toml` or `~/.config/insitio/nsit.toml` elsewhere; overridable with `NSIT_CONFIG_DIR` (tests).
- API: `Authorization: Bearer <token>`; errors `{"error":{"code","message"}}`; private repos 404 without access; no repo delete endpoint in v1; API never authenticates with session cookies.
- Device codes expire in 600 s; poll interval 5 s; user code format `XXXX-XXXX` from `BCDFGHJKLMNPQRSTVWXZ`; approved token name `nsit on <client_name>`.
- Secret guard patterns (names): `.env`, `.env.*` except `.env.example`/`.env.sample`, `*.pem`, `*.key`, `id_rsa*`, `id_ed25519*`, `*.p12`, `*.pfx`, `credentials.json`; content: `-----BEGIN [A-Z ]*PRIVATE KEY-----`, `(gfk|ins)_[A-Za-z0-9_-]{30,}`, `gh[pousr]_[A-Za-z0-9]{36,}`, `AKIA[0-9A-Z]{16}`, `.npmrc`/`.pypirc` containing `_authToken` or `password`. Overrides live in committed `.nsit-allow-secrets`.
- Release asset names: `nsit-windows-x64.exe`, `nsit-linux-x64`, `nsit-macos-arm64`, `nsit-macos-x64`, `SHA256SUMS`; release repo `a2thalex/gitfkd` (server config `NSIT_RELEASE_REPO`).
- Conventional Commits with the `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` trailer.

## Review Focus

1. **Paths with spaces and non-ASCII** (e.g. `C:\Users\Gregory\VideoInk - OG Edition`): every command works there and with `-C "<path>"` → test in Task 8.
2. **Not signed in, non-TTY** (agent with no `NSIT_TOKEN`): `nsit push`/`nsit repo list` exit 3 at once with a sign-in hint, never wait for input → test in Task 7.
3. **Windows `core.autocrlf=true`**: a fresh clone shows a clean `nsit status` and `nsit commit` commits nothing → test in Task 9.
4. **Push rejected or server unreachable mid-operation**: no local refs move, exit 6 (rejected) or 1 (network) with a one-line reason, no token in the message → test in Task 10.
5. **Larger real repositories** (thousands of commits, tens of MB): clone and push finish, progress only on a TTY → test in Task 12 using a generated repo with 2,000 commits and a 20 MB blob.
